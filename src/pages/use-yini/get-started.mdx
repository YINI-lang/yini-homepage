# Get Started with YINI

Welcome! This guide helps you create your **first working `.yini` file** in
under 2 minutes using the terminal.

YINI is a human-friendly configuration file format inspired by INI,
extended with nested sections, arrays, objects, and comments.

If you want to try YINI without installing anything, use the
[YINI Playground](/playground). This page focuses on the
[YINI CLI](/tools/yini-cli/), which is the simplest starting point for
local files and automation.

## Prerequisite: Node.js

Node.js is required to run the YINI command-line (CLI) tool.

You can check if Node.js is already installed by running:

```bash
node -v
```

If Node.js is not installed, download it from:
[https://nodejs.org ↗](https://nodejs.org)

It's recommended to use **Node.js 20 or later**.

---

## 1) Install yini-cli (or just use npx)

**Option A - use without installing**

```bash
npx yini-cli --help
```

**Option B - enable yini CLI globally**

```bash
npm i -g yini-cli
```

**Option C - add the CLI to your Node.js project**

```bash
npm i -D yini-cli
```

By default, `yini parse` prints formatted JSON to the terminal.

If you want a fuller introduction, examples, and common commands, see the
[YINI CLI page](/tools/yini-cli/).

---

## 2) Create your first .yini file

Save this as `config.yini`:

```yini
^ App
  name = "Demo"
  version = "1.0.0"
  features = [ "search", "dark-mode" ]  // Comments are allowed

^ Database
  host = "localhost"
  port = 5432
  auth = { user: "admin", pass: "secret" }  // Object literal
```

**Notes:**

- **Sections:** start with `^`. Add more carets for nesting
  (sub-sections): (`^`, `^^`, `^^^`, ...).
- **Members:** written as `key = value` pairs.
- **Comments:** Use `//` or `#` for inline comments; no whitespace is
  required after `#`.
- **Arrays:** `[1, 2, 'three']`
- **Objects:** `{ key: 'value', n: 1 }`
- **Strings:** must be quoted `'like this'` or `"like this"`.
- For more details, see:
  [Learn the YINI format](../learn-yini/learn-yini-config-format).

Coming from INI? YINI keeps the same familiar key-value style but adds
nesting, lists, and objects without changing how basic configs look.

## 3) Parse your `.yini` file

Once your file is saved, parse it with the CLI.

If you used **option A** with `npx` in step 1:

```bash
npx yini-cli parse config.yini
```

Or, if you used **option B or C** (using npm) in step 1:

```bash
yini parse config.yini
```

By default, `parse` outputs formatted JSON:

```json
{
    "App": {
        "name": "Demo",
        "version": "1.0.0",
        "features": ["search", "dark-mode"]
    },
    "Database": {
        "host": "localhost",
        "port": 5432,
        "auth": { "user": "admin", "pass": "secret" }
    }
}
```

## Now you have a working YINI file

You have now created a `.yini` file and parsed it to JSON.

The core flow is:

- Create a structured `.yini` file.
- Run `yini parse` or `npx yini-cli parse`.
- Use the JSON output in tools, scripts, or applications.

💡 Common tips:

- Keys and section names are case-sensitive.
- Strings must always be quoted, either `'` or `"`.

## More CLI options

Once the basic parse works, you can adjust the output style or write the
result to a file.

### Compact JSON

To output minified JSON with no extra whitespace:

```bash
yini parse config.yini --compact
```

### JavaScript-style output

To output a JavaScript-style object instead of JSON, use the `--js` flag.

```bash
yini parse config.yini --js
```

### Explicit JSON output

Formatted JSON is the default, but you can request it explicitly:

```bash
yini parse config.yini --json
```

### Write output to a file

To save the result:

```bash
yini parse config.yini -o output.json
```

YINI CLI avoids accidentally replacing newer output files by default. For
the full output and overwrite option reference, see the
[YINI CLI page](/tools/yini-cli/).
