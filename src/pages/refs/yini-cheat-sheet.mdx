# YINI Cheat Sheet

> _Based on the official **YINI Specification (v1.0 Release Candidate)**_

A **quick reference** for writing clean, readable YINI configuration files.

YINI makes data files (such as configuration files and application settings) easy for humans to read 
**and** predictable for machines to process — like INI, but with **real structure**, lists (arrays), objects, and comments.

More structured than INI, less noisy than JSON, and less fragile than YAML.

---

## 🧱 Basic Syntax

| Element                           | YINI Syntax                                                                                                                |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Section heading: level&nbsp;1** | `^ App`                                                                                                                    |
| **Section heading: level&nbsp;2** | `^^ Database`                                                                                                              |
| **Section heading: level&nbsp;3** | `^^^ Pool`                                                                                                                 |
| **String**                        | `"text"`, `'text'`, `"C:\Users\Robin"` <br/>👉 Strings are raw by default — `\` and `\n` are treated as normal text |
| **Number**                        | `42`, `3.14`, `-10`, `1e4`                                                                                                        |
| **Boolean**                       | `true`, `false`, `on`, `off`, `yes`, `no` _(case-insensitive)_                                                             |
| **Null**                          | `null`, `Null`, _(or blank in lenient mode)_                                                                               |
| **List / Array**                  | `[1, 2, 3]`                                                                                                                |
| **Inline object (map/dict)**      | `{ a: 1, b: 2 }`                                                                                                           |
| **Comment**                       | `// Default comment`                                                                                                       |
| **Alt. comment**                  | `# Comment` _(must be `#␠` or `#\t`)_<br/><br/> ❌ `#Missing space before comment start`<br/> ✅ `# This is an OK comment` |
| **Multi-line (block) comment**    | `/* comment */`<br/><br/>`/*`<br/>`  Multi-line`<br/>`  comment`<br/>`*/`                                                  |
| **Full-line comment**             | `; This is a full-line comment (only full lines)`                                                                          |
| **Disable line**                  | `--debug = true`                                                                                                           |

---

### 📝 Naming Rules

- **Section names** and **keys** can include spaces.
- Use backticks (<code>`</code>) for special characters or reserved words:

```yini
^ `My App`
`api-key` = "abc123"
`user.name` = "Alex"
```

#### 💡 Style Convention (Optional)

- Section names typically start with a Capital letter.
- Keys typically start with a lowercase letter.

_This is a readability convention — not a requirement._

## 🧩 Inline Objects & Nested Data

(Objects are also called maps or dictionaries in general sense.)

### Simple object

```yini
db = { host: "localhost", port: 5432 }
```

### Nested objects

```yini
service = {
    http: { port: 8080, secure: true },
    limits: { rpm: 1000 }
}
```

---

## 🧭 Important Rules

- **Indentation is cosmetic** — structure is defined by section markers (`^`, `^^`, `^^^`, etc.).
- **Strings must be quoted** using `'...'` or `"..."`.
- Inside a section, `name: "John"` creates a **list**.  
  Use `name = "John"` for a single value.
- Trailing commas are allowed in **lists and objects** _(lenient mode)_.
- Duplicate keys are **disallowed by default**.
- `#` starts a comment **only if followed by a space or tab**.

## 🔢 Number Formats

YINI supports multiple numeric formats:

| Format      | Example                                                                                       |
| ----------- | --------------------------------------------------------------------------------------------- |
| **Integer**     | `42`, `-42`<br/><br/> ❌ `01` (leading zero not allowed)<br/> ✅ `1`<br/> ✅ `0`                |
| **Float**       | `3.14`, `-3.14`<br/><br/> ❌ `3,14`<br/> ✅ `0.14`                                                     |
| **Scientific (base-10)** | `1e6`, `5.2E-3`                                                                               |
| **Hexadecimal (base-16)** | `#FFAA00`<br/><br/> ❌ `# FFAA00` (parsed as a comment)<br/> ✅ `#ffaa00` |
| **Binary (base-2)** | `0b101010`                                                                                    |
| **Octal (base-8)** | `0o755`                                                                                       |
| **Duodecimal (base-12)** | `0z2BA9`, `0z2EX9`<br/><br/>Digits: `0–9`, `A` or `X` = 10, `B` or `E` = 11 _(case-insensitive)_<br/>💡 `0z10` equals decimal 12. |

All numeric forms are parsed as real numbers — no quotes required.

## 🧪 Example 1 — Minimal Real-World

```yini
^ App
name = "Nebula"
version = "2.3.1"

^^ Network
ports = [80, 443]
ssl = true   // boolean (case-insensitive)

^^ `Rate Limits`
requests = { perMinute: 1200, burst: 60 }
timeout = null
```

---

## 🧪 Example 2 — Practical Config with Comments

```yini
# Optional YINI marker
@yini

^ Service
name = 'Aurora'                 # Single quotes
path = 'C:\Program Files\App'   # Backslashes are raw (no escaping needed)
enabled = Off                   # Boolean (case-insensitive)
retries = 3

    ^^ Database
    host = 'localhost'
    port = 5432
    color = #336699             # Hex number literal

    ; This is a full-line comment (for humans)
    --password = 'secret'       # Disabled line (ignored by parser)

        ^^^ Limits
        maxUsers = 1000
        timeout =               # Blank value → null (lenient mode)
```

> 💡 **Note:**  
> Lines prefixed with `--` are **disabled configuration lines**.  
> They behave like comments (the parser ignores them), but are intended to temporarily disable
> real configuration — not to serve as documentation.
>
> In editors, they are typically highlighted differently from normal comments to indicate
> “disabled code” rather than explanatory text.
